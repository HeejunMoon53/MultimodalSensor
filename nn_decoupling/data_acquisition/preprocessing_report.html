2. Raw vs 필터링 — 노이즈 처리 전략

문제 왜 IIR 필터가 동적 구간에서 오차를 유발하는가

1차 IIR (지수이동평균): y[n] = (1−α)·y[n−1] + α·x[n]
시간상수 τ ≈ T_s / α 이므로:

파라미터α = 0.2 (TENG)α = 0.02 (R_DC)
τ (시간 지연)~50 ms~500 ms
10 mm/s 이동 시 위치 오차0.5 mm5 mm

→ 센서가 이동 중인 구간에서 필터 출력값은 현재 물리 상태와 일치하지 않음. 모델은 지연된 dL/dR과 현재 시각의 eps/d를 매핑하도록 학습되어 동적 오차가 크게 발생.

비추천 인과 IIR / 이동평균

  • 정상 상태(Steady-state)에서는 노이즈 저감 효과 있음
  • 이동 구간에서 위상 지연(phase lag) → 레이블 불일치
  • α가 작을수록(강한 필터) 지연이 심화
  • 저번 학습에서 오차가 컸던 주된 원인

권장 Raw 데이터 학습

  • 노이즈가 zero-mean, 가우시안에 가까울 경우 모델이 통계적으로 평균화
  • 레이블(eps, d)과 입력(dL, dR)이 동일 시각에 대응 → 지연 없음
  • 배치 내 충분한 샘플로 노이즈 영향 흡수 (배치 크기 ≥ 256 권장)
  • 이동 구간과 정지 구간 모두 포함 → 동적 범위에서도 일반화

대안 Median Filter (위상 지연 없음)

IIR 대신 홀수 윈도우 중앙값 필터를 사용하면 위상 지연이 없고 impulse spike 제거 효과도 있음. 단, 학습 시 center-mode로 적용해야 하며 추론 시에는 실시간 causal 적용 불가하므로 임베디드 배포와 호환성 문제 발생.

방법위상 지연스파이크 제거임베디드 호환
IIR (α=0.02)~500 ms ❌보통✅
IIR (α=0.2)~50 ms ⚠️약함✅
Median (w=5)0 (center) ✅강함❌ (causal)
Raw (권장)0 ✅없음✅

결론: Raw 데이터로 학습, 노이즈는 배치 크기와 데이터 양으로 처리.

3. 이상치(Overflow/Spike) 제거

LDC1614 레지스터 포화(Saturation)

LDC1614가 공진 주파수를 정상 측정하지 못할 때 레지스터 최대값(0x0FFFFFFF = 268,435,455)을 반환함. 이 경우 계산되는 dL_pct = (L0/ldc_raw)² − 1 값이 물리적으로 불가능한 범위로 급락.

물리적 유효 범위

신호물리 하한물리 상한제거 기준
dL_pct −30 %+25 % |dL| > 30 % 또는 ldc_raw ≥ 0.99 × 2²⁸
dR_pct −5 %+25 % dR < −5 % 또는 dR > 30 %

단발 스파이크 (Impulse) 제거

단일 샘플이 이웃 샘플 대비 급격히 튀는 경우: |x[n] − median(x[n−2:n+3])| > 3 × rolling_std를 이상치로 판단. 현재 두 데이터셋에서 5σ 기준 스파이크 0건이지만, 더 민감한 3σ 기준 적용 권장. 

# 이상치 마스킹 예시
def remove_outliers(df):
    dL = df["dL_pct"].values
    dR = df["dR_pct"].values

    # 물리 범위 클리핑
    dL_ok = (dL > -30) & (dL < 25)
    dR_ok = (dR > -5)  & (dR < 30)

    # 단발 스파이크: rolling median 대비 3σ 초과
    s = pd.Series(dL)
    med = s.rolling(5, center=True, min_periods=1).median()
    std = s.rolling(50, center=True, min_periods=1).std().fillna(s.std())
    spike_L = (dL - med.values).abs() > 3 * std.values

    s2 = pd.Series(dR)
    med2 = s2.rolling(5, center=True, min_periods=1).median()
    std2 = s2.rolling(50, center=True, min_periods=1).std().fillna(s2.std())
    spike_R = (dR - med2.values).abs() > 3 * std2.values

    mask = dL_ok & dR_ok & ~spike_L & ~spike_R
    return df[mask].reset_index(drop=True)

주의 제거 후 시간 연속성이 끊기므로 시계열 모델 사용 시에는 연속 구간으로 재분할 필요.

  • 커버리지 보완: 143611이 각 strain 레벨에서 d 전체를 커버하므로 더 균일한 (eps, d) 분포 제공
  • 가중치 조정 불필요: 두 파일 샘플 수가 비슷하고(10만 vs 8.8만) 물리 범위도 겹침

핵심 병합 전 각 파일에서 독립적으로 baseline(L0, R0) 계산하거나, 두 파일 공통의 정지 구간(eps≈0, d≈36mm)에서 baseline을 통일. 현재 CSV에는 이미 dL_pct, dR_pct가 계산되어 있으므로 baseline 일관성 확인 필요.

5. 다운샘플링 / 업샘플링

권장 다운샘플링 — 10~20 Hz (stride 5~10)

현재 ~100 Hz 수집. 스테퍼 모터 최대 속도 5 mm/s 기준으로 10 ms(100 Hz)마다 신호 변화량:

신호100 Hz에서 10 ms 변화량신호 노이즈(σ)SNR
dL (d 변화 시)~0.05 %~10 %~0.005 → 극히 낮음
dR (eps 변화 시)~0.003 %~6 %~0.0005 → 극히 낮음

→ 인접 100 Hz 샘플 간에는 거의 새로운 정보가 없음 (높은 시간 자기상관). stride=5 (20 Hz)로 다운샘플하면 데이터 크기 5× 감소, 학습 속도 향상, 자기상관 문제 완화. 신호 정보 손실 없음. 

# stride 다운샘플링 (시간 정렬 보존)
STRIDE = 5  # 100 Hz → 20 Hz
df_down = df.iloc[::STRIDE].reset_index(drop=True)

비권장 업샘플링

현재 데이터 총 약 188,000 샘플 (20 Hz 기준 37,600 샘플). 이미 충분한 양이므로 업샘플링 불필요. SMOTE·보간 방식 업샘플링은 물리적으로 존재하지 않는 샘플을 생성하여 PINN loss와 충돌 가능 → 적용하지 않음.

6. 구간 분할 전략

Point-wise vs Sequence 모델 선택

접근설명장점단점
Point-wise (권장) 각 (dL, dR) 샘플 → 독립적으로 (eps, d) 예측 기존 구조 유지, STM32 O(1) 추론, shuffle 가능 시간 컨텍스트 미활용
Sequence (LSTM/TCN) N샘플 윈도우 → 현재 시각 예측 노이즈 문맥 학습, 동적 추적 가능 복잡도 증가, 임베디드 메모리 문제, 시간 정렬 분할 필수

정지 vs 이동 구간 분류 후 처리

두 데이터셋 모두 xa·d 이동 중인 샘플 비율이 낮음(<1%). 이동 구간은 레이블이 불확실하므로 제외 후 정지 구간만 학습하는 것이 가장 깨끗한 접근. 단, 동적 상황에서 추론 성능이 낮아질 수 있음. 

# 이동 구간 감지 및 제외
def mask_steady(df, eps_mm=0.1, d_mm=0.1):
    """xa, d 가 eps 이상 변하는 구간을 이동 중으로 판단."""
    xa_diff = df["xa_mm"].diff().abs().fillna(0)
    d_diff  = df["d_act_mm"].diff().abs().fillna(0)
    moving  = (xa_diff > eps_mm) | (d_diff > d_mm)
    # 이동 직후 settling time (앞뒤 각 50 샘플 = 0.5s @100Hz) 제외
    moving  = moving.rolling(50, center=True, min_periods=1).max().astype(bool)
    return df[~moving].reset_index(drop=True)

settling 여백 센서 물리 시정수(LDC1614 변환시간 ~200 µs, ADC settling ~100 µs)는 충분히 빠르지만 스테퍼 모터 정지 후 기계적 진동이 수십 ms 지속될 수 있으므로 이동 이후 ~0.5 s 를 추가 제외하는 것이 안전.

7. Train / Val / Test 분할

비추천 전체 데이터를 시간 순서 무시하고 무작위 셔플

100 Hz에서 인접 샘플은 거의 동일한 (eps, d) 상태. 무작위 80/10/10 분할 시 test 샘플의 99% 이상이 train 샘플과 같은 (eps, d) 상태로 인접 → data leakage. 실제 일반화 성능이 과대평가됨.

권장 A 파일 단위 분할 (프로토콜 독립성 검증)

Train: 140039 (Ramp, ~100k)
Val: 143611 앞 20%
Test: 143611 뒤 80%
  • 140039(Ramp)로 학습, 143611(Oscillate)로 테스트 → 프로토콜 일반화 검증
  • 두 프로토콜이 물리 범위를 다르게 커버하므로 외삽 능력까지 평가 가능
  • 가장 엄격한 평가. 논문 제출용으로 적합

권장 B (eps, d) 그리드 기반 분할

Train: 전체 (eps, d) 그리드 70%
Val 15%
Test 15%
  • 전체 (eps, d) 공간을 격자로 나누어 각 셀에서 train/val/test 분배
  • 두 파일 모두 활용 → 더 많은 학습 데이터
  • 같은 물리 상태에 속한 샘플을 함께 분류하여 leakage 방지
  • 구현 복잡도 높음

Raw 학습 시 Physics Loss는 그대로 유지. 오히려 Raw 노이즈 환경에서 물리 제약이 정규화 역할을 하여 과적합 억제 효과가 더 커질 수 있음. λ warmup 전략(초반 data loss만, 이후 점진 증가)도 그대로 적용.
