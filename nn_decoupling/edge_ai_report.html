🔍 6b. INT8 양자화 해상도 분석 — Staircase Effect

관찰된 현상: 실측 CSV(realtime_EI_20260601_161314.csv)에서 추론 결과(eps_ei_pct, d_ei_mm)가 여러 행 동안 완전히 동일한 값을 유지했다가 특정 시점에 계단식으로 점프하는 패턴이 관찰됨. 이는 INT8 양자화로 인한 출력 해상도 이산화(discretization)에 의한 것이다.

해상도 계산 원리 (How to derive INT8 resolution)

stedgeai INT8 PTQ는 per-tensor symmetric 양자화를 사용한다. 각 신호의 물리적 해상도는 양자화 스케일 × 정규화 표준편차로 결정된다.

단계수식의미
① 정규화 x_norm = (x − μ) / σ StandardScaler 역할. μ, σ는 훈련 데이터 통계.
② INT8 변환 (입력) x_i8 = round(x_norm / S_in) S_in = stedgeai per-tensor 입력 스케일. x_i8 ∈ [−127, 127].
③ 1-step 크기 (입력) Δx = S_in × σ 입력 신호가 이 크기를 바꿔야 int8이 1 바뀜.
④ Dequantize (출력) y = y_i8 × S_out × σ_y + μ_y S_out = stedgeai 출력 스케일. 역정규화 포함.
⑤ 1-step 크기 (출력) Δy = S_out × σ_y 출력 int8이 1 바뀔 때 물리 출력이 이만큼 점프. 
/* nn_inference.c 에서 사용하는 스케일 상수 (stedgeai 자동 생성) */
/* S_in/S_out 은 ONNX QDQ 노드의 scale 파라미터 */

/* Stage1 — dR → eps */
S1_IN_SCALE  = 0.014863119f  /* dR_norm  → int8 */
S1_OUT_SCALE = 0.014087991f  /* int8     → eps_norm */

/* Stage2 — [dL, eps] → d */
S2_IN_SCALE  = 0.032876834f  /* [dL_norm, eps_norm] → int8  (per-tensor: 두 입력 공유) */
S2_OUT_SCALE = 0.013291485f  /* int8     → d_norm */

/* StandardScaler 통계 (decoupler_params.h) */
SC_DR_STD  = 5.469%  SC_DL_STD  = 8.003%
SC_EPS_STD = 8.602%  SC_D_STD   = 10.478mm

/* 예시 계산: dR 1 int8 step이 물리 신호에서 얼마인가? */
dR_step = S1_IN_SCALE × SC_DR_STD = 0.014863 × 5.469 = 0.0813%
eps_step = S1_OUT_SCALE × SC_EPS_STD = 0.014088 × 8.602 = 0.1212%

신호별 Float32 vs INT8 해상도 비교

Float32 해상도는 하드웨어 노이즈로 결정된다. dR: ADC 12-bit + IIR(α=0.02) → 실측 정지 노이즈 ~0.015%. dL: LDC1614 28-bit → 추정 ~0.001%.

위치신호 Float32 유효 해상도 INT8 1-step 크기 저하 배율 유효 계단 수 (전 범위)
S1 입력 dR ~0.015% (ADC+IIR) 0.081% / step 5.4× 0~30% → 239 steps
S2 입력 dL ~0.001% (LDC 28-bit) 0.263% / step 263× −30~+20% → 179 steps
S1 출력 eps (ε) ~연속 (float) 0.121% / step — 0~30% → 248 steps
S2 입력 eps (S2 재정규화) 0.121% (S1 출력 제한) 0.283% / step 2.3× S1 출력 2.3개당 S2 1-step
S2 출력 d (mm) ~연속 (float) 0.139 mm / step — 0~50mm → 254 steps
주목: dL이 Float32 대비 263배 해상도 저하. LDC1614가 28-bit 고해상도 센서임에도 INT8 병목으로 대부분 버려진다. dR(5.4×)와 비교해 dL이 훨씬 심한 이유는 S2_IN_SCALE이 S1_IN_SCALE보다 2.2배 크기 때문 (두 입력을 공유하는 per-tensor 스케일의 한계).

Float32 모델 어떤 속도도 연속값 그대로 완전 연속 (hardware 한계만) 양자화 없음 → 계단 효과 없음
논문 보고 권장사항: Test MAE 단독 보고는 계단 효과를 은닉한다.
① 신호 해상도: Δε = 0.121%/step, Δd = 0.139 mm/step
② 유효 계단 수: ε 248계단 (0–30%), d 254계단 (0–50mm)
③ Dead-zone: 정지 시 dR 노이즈(0.015%) < 1-step(0.081%) → 출력 분해능 제로
⇒ INT8은 메모리·속도 우위를 가지나, 느린 신호에서 Float32 대비 5.4–263× 해상도 저하가 발생함. PINN(818p) 교체 시 INT8 Flash 0.8KB → 해상도 문제는 동일하나 Flash 여유로 캐시 최적화 여지 증가.

/* ΔL/L₀, ΔR/R₀, ΔV/V₀ [%] 계산 */
int TDM_Get_Sensor_pct(float *dL, float *dR, float *dV) {
    if (!cal_done) return 0;
    uint64_t ldc_rs = ((uint64_t)cal_base_ldc * 100000) / g_SensorData.ldc_ch[0];
    uint64_t ldc_L  = (ldc_rs * ldc_rs) / 10000;  /* L_now/L_base × 10^6 */
    uint64_t r_rat  = ((uint64_t)g_SensorData.r_dc_adc[0] * 1000000) / cal_base_r;
    uint64_t v_rat  = ((uint64_t)g_SensorData.teng_adc[0] * 1000000) / cal_base_teng;
    *dL = (float)((int64_t)ldc_L - 1000000) / 10000.0f;
    *dR = (float)((int64_t)r_rat - 1000000) / 10000.0f;
    *dV = (float)((int64_t)v_rat - 1000000) / 10000.0f;
    return 1;
}

AI 추론 엔진 (decoupler.c — INT8 핵심)

/* INT8 matmul: int32 누산 후 dequantize */
static void linear_i8(const int8_t *W, float scale, const float *b,
                      const float *x, float *y, int in, int out) {
    for (int i = 0; i < out; i++) {
        int32_t acc = 0;
        for (int j = 0; j < in; j++)
            acc += (int32_t)W[i*in+j] * (int32_t)(x[j]/scale*127.0f);
        y[i] = acc * scale * scale / 127.0f + b[i];
    }
}

🔧 12. 최적화 기법 적용

A. INT8 PTQ (Post-Training Quantization) — 메모리 4× 압축

양자화 항목방식효과
가중치 형식 float32 → int8 (per-tensor symmetric) 4× 메모리 절감 (196 KB → 49 KB)
활성화 형식 float32 → int8 (QDQ) 레이어간 int8 유지 → dequant 최소화
제로포인트 0 (symmetric) — 덧셈 오프셋 연산 제거 연산 단순화
Scale 결정 정적 캘리브레이션 (500 샘플) 동적 range와 달리 추론 시 오버헤드 없음

✅ 14. 결론 — Edge AI의 성능과 필요성

본 연구에서 2-Stage MLP INT8 모델을 STM32G473CBT6에 임베딩한 결과, PC 기반 대비 다음과 같은 정량적 우위가 확인되었다.

⏱ 실시간성: 26–40× 빠른 E2E 응답

PC 기반 USB 통신 지연(20–40 ms)을 완전히 제거. 1 ms TDM 주기 내 추론 완료(284 µs). 로봇 안전 제어·햅틱 피드백 등 실시간 응용에서 결정적 우위.

⚡ 에너지 효율: 12,500–21,000× 절감

추론당 에너지 ~14 µJ vs PC ~175–300 mJ. 배터리 구동 웨어러블·IoT 센서에서 PC 기반 방식은 근본적으로 불가능.

💾 메모리: INT8 49 KB (Flash 38.4%)

float32 196 KB는 128 KB Flash 초과로 배포 불가. INT8 PTQ로 4× 압축 달성하면서 정확도 손실 <0.1% 유지. 양자화 없이는 이 MCU에서 배포 자체가 불가.

🤖 자율성: PC 연결 불필요

독립 동작으로 웨어러블·로봇·IoT 적용 가능. PC 기반은 상시 연결이 필요해 실제 착용·이동 시나리오에 부적합.

🎯 정확도: <0.1% 양자화 손실

Δε=0.020%, Δd=0.032 mm — 센서 노이즈 수준보다 낮아 실질적 성능 저하 없음. 연구 목표 정확도를 유지하면서 하드웨어 제약을 만족.
